# resc v0.2.0 — Reviewed diagnostics and executable skills

- Unified `resc_cli.py` commands for header inspection, read-only Windows driver inventory, native overlay repair/extraction, evidence audit and guarded USB reuse.
- One-command installer publishes both client configurations, five skills, runtime scripts and the `resc` wrapper. Preview is the default; apply preserves unrelated settings and keeps backups.
- Header evidence includes GPT CRC/geometry, FAT FSInfo, exFAT checksums, NTFS USA fixups and ext-family signatures. Read errors stay explicit and outputs cannot overwrite existing files.
- Limited Python MCP diagnostics work without building Rust. The backend advertises its actual tool set; native recovery remains required for sessions, WAL, jobs and extraction.
- Existing USB reuse requires an exact device preview token and explicit format data-loss acceptance; synthetic guards cover protected disks and pagefiles.

## Windows quick start

Download and extract `resc-v0.2.0-windows-x64.zip` to a permanent folder. It contains the Windows engine, source, skills and scripts. Python 3.11+ is required; Rust compilation is unnecessary for this bundle.

```powershell
python scripts/install.py --client both --apply
python scripts/resc_cli.py doctor
```

Restart your client to reload MCP and skills. Ask for `recovery-triage` with an acquired image path and a separate output location. The installer does not modify PATH; the wrapper location is printed.

## Validation and limits

The release workflow tests the new integration, 16 native E2E groups and synthetic USB guards against its freshly built engine before uploading assets. CI also runs Rust formatting, clippy, workspace tests and the recovery suites on Windows/Linux.

Local Windows checks passed all runnable Python suites, including 16 new integration tests and 16 E2E groups. Linux-only acquisition, optional FFmpeg decode and platform-specific filesystem checks are explicitly skipped when unavailable. Local debug Rust validation encountered a missing GCC runtime and Windows Application Control restrictions; clean CI provides those checks.

No physical USB recovery, hardware reset or driver modification is claimed. Python diagnostics are not a replacement for native WAL/session/job support. In-place source repair, guessed VBR synthesis and automatic Registry/driver changes are excluded.

Standalone `mcp-server.exe` and SHA-256 files are also attached. Verify the checksum before use. See `docs/v5-integration-review.vi.md` for the detailed review and limitations.
